# BMray

Версия 0.1.7: под названиями серверов показаны протокол, транспорт и защита
(например, `VLESS / XHTTP / REALITY`). Клиентский Xray JSON с Hysteria2
использует встроенный Xray 26.9.9 на Android. В версии 0.1.9 список серверов
показывает длинные названия в одну строку с многоточием, а крупная кнопка
подключения закреплена в верхней части экрана. Шестерёнка слева открывает
экран настроек с разделами «Пинг», «Информация» и «Логи». Логотип в приложении и иконки
Android/iOS созданы из изображения, предоставленного владельцем репозитория.

Новые тестовые APK и AAB публикуются в [GitHub Releases](https://github.com/ROikkrl/BMray/releases)
после успешной сборки `main`. Каждый новый выпуск требует повышения версии в
`pubspec.yaml`; тестовые APK подписываются одноразовым ключом.

Версия 0.1.6: VLESS XHTTP на Android подключается через отдельный Xray 26.9.9,
в том числе при импорте Xray JSON с `xhttpSettings.extra`. VPN-трафик остальных
приложений остаётся в sing-box TUN, а выбранный XHTTP outbound обслуживает Xray
через локальный SOCKS. Proxy GET также использует Xray. Ядро Xray упаковывается
для arm64-v8a и x86_64; iOS XHTTP пока не поддерживает.

Версия 0.1.5: подписки показывают все распознанные VLESS XHTTP записи с
названиями и явным статусом «XHTTP требует ядро Xray»; подключение и Proxy GET
через них отключены, чтобы не подменять транспорт TCP. Поддерживаемые записи
выбираются автоматически. Xray JSON с VLESS gRPC REALITY теперь конвертируется.
Серверный JSON Remnawave с `inbounds` и без клиентских `outbounds` не является
подпиской: адрес, UUID и публичный ключ берутся из клиентской выдачи панели.

Версия 0.1.4: серверное название подписки декодируется также из Base64URL без
дополнения. Proxy GET пробует три HTTPS-адреса по очереди через выбранный
outbound. Xray JSON можно импортировать как текст или HTTPS-подписку; VLESS TCP
REALITY и основные прямые правила конвертируются. XHTTP и Xray `leastPing`
балансировщик не поддерживаются sing-box 1.13, поэтому резервные каналы
пропускаются и ограничение показывается рядом с подпиской. Ссылки `type=xhttp`
не маскируются под обычный TCP.

Версия 0.1.3: подписки получают имя из заголовка `profile-title` или строки
`#profile-title:` в теле ответа (в том числе UTF-8 Base64). Введённое вручную
название не перезаписывается при обновлении. Подписки и серверы представлены
списками. Proxy GET проверяет HTTPS через выбранный sing-box outbound, TCP
проверяет порт напрямую через физическую сеть Android, ICMP запускает
системный ping при отключённом VPN. Проверка отображает `—` при ошибке или
тайм-ауте; результат одного метода не считается результатом другого.

Исходный код мобильного клиента подписок на базе Flutter и sing-box (libbox).
Пользователь вставляет **HTTPS-подписку или ссылку отдельного сервера**, выбирает
сервер и подключается через системный VPN. Домен `bolvankamax.com` использован
для идентификатора приложения `com.bolvankamax.bmray`; серверы и подписки
принадлежат пользователям, домен не обслуживает VPN трафик.

## Возможности и форматы

- Android: `VpnService` + sing-box, Xray для VLESS XHTTP; iOS: `PacketTunnelProvider` + sing-box.
- Импорт и обновление HTTPS подписок, выбор подписки и узла, подключение/отключение.
- Прямой импорт ссылок VLESS/VMess/Trojan/Shadowsocks/Hysteria2/TUIC через кнопку «+».
- Журнал подключения с копированием через кнопку журнала в верхней панели.
- Ссылки и узлы хранятся в защищённом хранилище устройства.
- Поддерживаются sing-box JSON с `outbounds`, текстовый список ссылок и
  base64 с ссылками `vless://`, `vmess://`, `trojan://`, `ss://`,
  `hysteria2://`, `hy2://`, `tuic://`.
- Clash YAML: распространённые узлы VLESS, VMess, Trojan, Shadowsocks,
  Hysteria2 и TUIC, включая обычные WebSocket/gRPC и Reality. Уникальные
  расширения Mihomo/Clash и проприетарные форматы ботов пока не поддерживаются.
  Если конкретная подписка не распознана, в боте попробуйте формат sing-box.

## Сборка Android кнопкой на GitHub

Версия 0.1.2 исправляет совместимость REALITY на Android; проверка ключа
сервера остаётся обязательной. Версия 0.1.1 добавляет прямой импорт серверов. На Android имя VPN-сервера
разрешается через DNS выбранной физической сети; сокеты ядра привязываются к
этой сети, а переключение Wi-Fi/мобильной сети больше не сбрасывается событием
отключения предыдущей сети. MTU по умолчанию — 1500; DNS на порту 53 явно
перехватывается до правил локальной сети. При проблемах с трафиком подключитесь,
попробуйте открыть сайт, затем откройте журнал и скопируйте ошибку.

Готовый APK доступен в [Releases](https://github.com/ROikkrl/BMray/releases).
Откройте **Actions → Android APK and AAB → Run workflow → Run workflow** для повторной сборки.
После успешного завершения откройте запуск и скачайте архив
`BMray-android-test-<номер>` в разделе **Artifacts**. Для скачивания нужно
войти в GitHub. Архив содержит APK для установки и AAB для проверки сборки.
Файлы хранятся 14 дней; повторный запуск создаёт новые.

Эти пакеты подписаны временным **тестовым** ключом и не предназначены для
Google Play. При установке следующей тестовой сборки может потребоваться
сначала удалить предыдущую (при этом удалятся сохранённые подписки).
Для публикации используйте постоянный собственный keystore, как описано ниже.
Тестовые APK и AAB также можно собрать локально:

```sh
bash scripts/build_android_test.sh
```

## Сборка Android для публикации (APK и AAB)

Нужны Flutter SDK 3.47+, Android SDK (API 36), JDK 17, Go 1.25.10,
Android NDK 28.0.13004108 и интернет для загрузки зависимостей.
Начиная с 0.1.2 ядро Android собирается из закреплённого исходного кода
sing-box 1.13.13 с патчем совместимости REALITY для новых серверов Xray.
Старый готовый `libbox.aar` больше не используется. Сборка через GitHub Actions
устанавливает зависимости и собирает ядро автоматически; локально задайте
`ANDROID_HOME` и выполните `bash scripts/build_libbox_android.sh`.
Перед сборкой APK скрипт также скачивает закреплённые исполняемые файлы Xray
26.9.9 для Android и сверяет SHA-256.
Описание патча и проверок: [patches/sing-box](patches/sing-box/README.md).

Для подписанной сборки создайте **свой** keystore и храните его вне проекта:

```sh
keytool -genkeypair -v -keystore /secure/path/bmray-upload.jks \
  -alias bmray -keyalg RSA -keysize 3072 -validity 10000
export BMRAY_KEYSTORE_FILE=/secure/path/bmray-upload.jks
export BMRAY_KEY_ALIAS=bmray
export BMRAY_KEYSTORE_PASSWORD='пароль-хранилища'
export BMRAY_KEY_PASSWORD='пароль-ключа'
bash scripts/build_android.sh
```

Полученные файлы: `build/app/outputs/flutter-apk/app-release.apk` и
`build/app/outputs/bundle/release/app-release.aab`. Сохраните keystore и пароли:
без них нельзя выпускать обновления приложения с прежней подписью.

## Сборка iOS (IPA)

Нужны Mac с Xcode, Flutter SDK 3.47+, CocoaPods и Apple Developer team с
возможностью подписать **оба** target: Runner и SingboxTunnel. Скрипт создаёт
расширение Packet Tunnel и его entitlements; Xcode/Apple должны разрешить
`Network Extensions` и `App Groups` для `com.bolvankamax.bmray` и
`com.bolvankamax.bmray.SingboxTunnel`. Перед сборкой задайте `DEV_TEAM` как
идентификатор своей Apple Developer team:

```sh
export DEV_TEAM=ВАШ_TEAM_ID
bash scripts/build_ios.sh
```

Скрипт получает `Libbox.xcframework.zip` из закреплённого релиза с проверкой
SHA-256 и создаёт `build/ios/ipa/*.ipa`. Первую сборку нужно проверить в Xcode
на физическом iPhone. Разрешение системного VPN запрашивается при первом
подключении. Профили подписи и сертификаты остаются под контролем владельца
Apple Developer аккаунта.

## Устройство проекта

- `lib/` — интерфейс, импорт и хранение подписок;
- `packages/vpn_plugin/` — исходники нативного моста (GPL-3.0), с исправлениями
  для имени пакета, бренда, проверки бинарников и выбора своего VPN профиля;
- `android/`, `ios/` — конфигурации платформ;
- `scripts/` — сборка релизных пакетов.

Код BMray и включённого плагина распространяется на условиях GPL-3.0; при
распространении приложения предоставляйте исходный код вместе с условиями
лицензии. Исходный код самого sing-box: https://github.com/SagerNet/sing-box.

## Статус проверки

Исходники парсера и генератора конфигурации проверены локальным smoke тестом
на base64/VLESS и Clash YAML. Конфигурации для шести распространённых типов
узлов Clash успешно прошли `sing-box check` в официальном бинарном выпуске
1.13.13.

24 сентября 2026 года для версии **0.1.2+3** `flutter analyze` и все
6 тестов импорта/конфигурации прошли успешно. Конфигурации Android и общего
режима прошли `sing-box check`.

Дополнительно выполнен интеграционный тест с настоящим Xray 26.9.9 на
loopback: Firefox и Chrome успешно передали по 136 КиБ HTTPS-данных через
VLESS Vision + REALITY. Неверные публичный ключ и short ID отклонены для
обоих отпечатков. Проверка ключа сервера не отключалась.

Ядро `1.13.13-bmray.1` собрано из исходников для Android arm64, armv7 и
x86_64. APK и AAB собраны с тестовой подписью на Flutter 3.47.5.
[Успешная сборка и скачивание файлов](https://github.com/ROikkrl/BMray/actions/runs/36059893288)
соответствуют коммиту `8d40d91b79f545d70cd7160f8a6053290c84932b`.

Запуск и VPN-трафик на физических устройствах, а также сборка iOS пока
**не проверены**. Перед публикацией нужны постоянная подпись, проверка
подключения с собственной подпиской и проверка трафика/DNS на устройствах.
